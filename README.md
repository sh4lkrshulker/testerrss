# Реестр заявок

Небольшой сайт для учебного задания: страница отправляет HTTP-запросы к API Supabase, а Supabase хранит записи в PostgreSQL. Сам сайт можно разместить на GitHub Pages. Компьютер не работает сервером и после публикации может быть выключен.

## Настройка базы

1. Создайте проект на [supabase.com](https://supabase.com/) и дождитесь его запуска.
2. Откройте **SQL Editor** в панели проекта, вставьте содержимое `database.sql` и нажмите **Run**. Создадутся таблица, правила доступа и три примера.
3. Откройте **Project Settings → API Keys**. Скопируйте **Project URL** и **publishable key** (`sb_publishable_...`; можно использовать старый `anon` key).
4. В `app.js` замените обе заглушки на скопированные значения. Project URL должен быть настоящим адресом вида `https://abcdefghijk.supabase.co`, а не текстом `your_project_id`; публичный ключ начинается с `sb_publishable_` (или это старый `anon` JWT).
5. Сохраните изменения и проверьте сайт по HTTPS-адресу GitHub Pages. Не открывайте его двойным щелчком как `file://`: браузер может заблокировать запросы к облачной базе. Для проверки до публикации используйте расширение Live Server.

## Публикация через GitHub Pages

1. Создайте новый репозиторий на GitHub и загрузите в него файлы этого проекта.
2. В репозитории откройте **Settings → Pages**.
3. В разделе **Build and deployment** выберите **Deploy from a branch**, ветку `main` и папку `/ (root)`, затем нажмите **Save**.
4. После публикации GitHub покажет адрес сайта в разделе Pages. Откройте его и проверьте список, создание и изменение заявки.

Изменения `app.js` и опубликованные файлы нужно загрузить в GitHub, чтобы они появились на сайте. Данные заявок сохраняются в Supabase отдельно и не пропадают при обновлении сайта.

## Что делает приложение

- Загружает записи через `GET`.
- Создаёт запись через `POST`.
- Изменяет запись и её статус через `PATCH`.
- Удаляет запись через `DELETE`.
- Ищет и фильтрует записи в браузере.

Для понятного учебного примера SQL разрешает любому посетителю читать, добавлять, изменять и удалять заявки. Поэтому сайт и база публичные: не заносите настоящие персональные или конфиденциальные данные. Ключ `publishable`/`anon` предназначен для браузера и может быть опубликован. **Никогда не вставляйте в `app.js` `service_role` key**: он обходит правила доступа и должен оставаться секретным.
